Katalyst Reputation Management

Handover Runbook

Getting the Coverage Desk and the daily tracker running in Nikhila's account. The order matters — each phase depends on the one before it. Roughly 45 minutes, plus 25 for the alerts.

0 of 0

1 · Before you log inYour account

Two things must be true before her account can do anything useful. Both are on your side.

Share the coverage workbook with her — as Editor

The workbook lives in anmolm@gmail.com's Drive. Her Claude reads and writes it through her Google account, so without a share she sees nothing. Editor, not Viewer — the tracker appends rows.

Open Katalyst_PR_Coverage_WORKING → Share → add nikhilapalat@gmail.com → Editor.

While you're there, change "Anyone with the link can edit" back to restricted. It's been open all afternoon.
Longer term the file should live in her Drive, not yours — she owns the data. Transfer ownership once things are stable; the file ID survives, so nothing breaks.

Import the deduplicated coverage

In that same sheet: select the ALL_COVERAGE tab → File → Import → Upload → ALL_COVERAGE_deduped.csv → Replace current sheet. Then add DUPLICATES_REVIEW.csv as a new tab the same way.

Both files are in your Nikhila-Katalyst folder. The file ID doesn't change, so the desk needs no edit.

Push the repo to GitHub

cd ~/Documents/Nikhila-Katalyst
gh repo create katalyst --private --source=. --remote=origin --push

Then install it on your Claude first — better to find a packaging problem on your login than on hers.

2 · Connect her toolsHer account

Nothing else works until these are authenticated as her.

Google Drive and Gmail — both, separately

Customize → Connectors → +, then connect each and follow the Google auth prompts.

Gmail is not optional. The tracker's fastest source is her Google Alerts email — without it, the daily run falls straight through to slow searching.

Check she can see the workbook

Ask her Claude: "open Katalyst_PR_Coverage_WORKING in my Drive and tell me how many rows are in ALL_COVERAGE." It should say 44. If it can't find the file, step 1.1 didn't take.

Look at her plan

Pro already includes Cowork, projects and Opus — her ceiling is usage, not access. If she's staying on Pro for now, that's workable; just expect report-building days to throttle. Max 5x is the fix when she's ready.

3 · Install the pluginHer account

This is the vehicle. Everything we build arrives — and updates — through it.

Add the marketplace, install katalyst

Customize → Plugins → Add marketplace → enter the repository → install katalyst from the list.

Private repo, so it needs git credentials once on her machine: gh auth login then gh auth setup-git. Do it now while you're sitting there. If it fights you, install from the plugin file instead and accept manual updates.

Confirm the skill loaded

Open the installed plugin — daily-coverage-tracker should appear under its Skills tab.

4 · Publish the Coverage Desk on her accountHer account

This one can't be shortcut. A page with connector access can't be shared — that's the platform protecting client data — so it has to be published from her login to be hers.

Attach the file and ask Claude to publish it

In a Cowork session on her account, attach artifacts/coverage-desk.html and send:

Publish this HTML file as an artifact exactly as written — do not
rewrite or redesign it.

Declare these capabilities:
  mcp, with the Google Drive connector and the read_file_content tool
  sample

Title: Katalyst Coverage Desk

Then open it and check the figures: 44 placements, 30 clients, 22 with nothing logged.

Tell her plainly: open it from the artifacts gallery, never from a saved file. Downloading the HTML and double-clicking it cannot work — the page has no data of its own. It now says so rather than hanging, but the instinct is worth heading off.

5 · Switch on the alertsNikhila

The single cheapest thing that changes any of these numbers. Twenty-five minutes, and it's hers to do — they land in her inbox.

Create the 30 Google Alerts

Signed in as nikhilapalat@gmail.com, go to google.com/alerts. Paste each query from the CLIENTS tab — they're already written, with the qualifiers each name needs.

Per alert: How often = As-it-happens, Sources = News, Region = India, How many = All results.

Tick Alert Created? in the sheet as she goes. The desk's readiness meter fills as she does.

6 · Schedule the daily trackerHer account

Set it to run in test mode first. Nobody's inbox should receive a run we haven't watched.

Create the task

Scheduled in the left sidebar → New task (upper right) → Set up manually. Frequency daily, early morning IST.

Run the daily-coverage-tracker skill for the Katalyst client roster.

TEST MODE IS ON: write new rows to a copy of the coverage workbook,
not the live one, and send the summary email to anmolm@gmail.com only
— not to Pooja, and not to Nikhila.

Leave test mode on until told otherwise.
Scheduled tasks run in the cloud and can't touch local folders — fine here, since everything lives in Drive and Gmail.

Trigger one run by hand and read the output

From the Scheduled list, run it manually. Check three things: it finished inside its time budget, the email arrived at your address, and the rows it logged are real coverage rather than directory listings.

After three clean runs, turn test mode off

Edit the task prompt: point it at the live workbook and let the email go to Pooja (CC Nikhila), as her original spec had it.

7 · VerifyBoth

The three checks that mean it's working

1. The desk on her account shows 44 placements and 22 silent clients.
2. The alert-readiness meter moves as she ticks the CLIENTS tab.
3. A manual tracker run appends a row and emails you.

If all three hold, tomorrow morning works without either of you touching it.
